# FieldDesk 固定做单执行规则

本文件只约束瑞云做单顺序和自动化安全边界，不改变 FieldDesk 的页面、账号、库存、信息员后台或返件设计。

## 唯一快速入口

资料齐全后使用 python agent.py --order 工单编号 --stage complete-order --close。同一浏览器会话连续执行，禁止拆成多个聊天任务逐页点击。

目标：不含大附件实际传输时间时，瑞云页面操作不超过 60 秒。每一步必须记录耗时；单个普通控件最多等待 4–5 秒，失败立即报告具体步骤，不允许无提示转圈。

## 固定顺序

1. 用物流单号打开唯一 RMA。
2. 一次上传 SN、开箱和外观照片；瑞云已有同名附件时跳过。
3. 填写 SN、签收明细，确认签收。
4. 签收后比较 SN 与项目号；一致时不查询飞书，不一致时才使用本地同步的机型汇总修正。
5. 进入检测：三级故障以实际核心更换件为依据；多配件优先电池、电机、主板、屏幕等核心件。责任判定、故障描述、是否拆封和拆封备注保持原值不动。
6. 保内/保外按 SN 和购买日期规则判断；冲突时停止，不猜测。
7. 进入内部维修单并使用“服务报告”，不得进入“备件申请单”。
8. 按完整物料编码添加实际使用配件，逐项核对数量；已保存的配件按断点记录跳过。
9. 维修措施使用“客诉现象复现 → 检测结果 → 更换配件 → 清理测试 OK 寄回”的完整话术；“是否是排障问题”固定选“是”；责任判定保持空白。
10. 一次上传师傅手机端已提交的维修照片和视频；瑞云已有文件时跳过。
11. 停在瑞云最终“完工/提交”动作之前。除非另有明确授权，Agent 永远不得点击最终动作。

## 禁止事项

- 做单过程中修改代码或切换项目副本。
- 重复读取整页、重复截图或每一步重新分析业务规则。
- 因为日志显示成功就假定瑞云已经保存；必须以当前远端页面核验。
- 找不到准确配件、三级故障、唯一工单或唯一控件时选择相近项代替。
- 使用 /Users/coco/Documents/New project 中的临时补丁替代正式仓库代码。

## 恢复和性能

- 每个成功动作写入 CRM已完成步骤；重试时重新读取瑞云，并跳过已确认完成的步骤。
- 优先复用保存的 RMA、维修单 URL 和持久登录会话。
- 只保留当前窗口截图作为结果或失败证据，不做整页截图。
- 附件上传耗时单独记录，避免把网络传输时间误判为页面自动化卡住。
