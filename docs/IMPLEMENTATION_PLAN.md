# FieldDesk 实施计划

## 1. 当前仓库基线（2026-07-28）

本计划基于当前 Git 历史和代码盘点制定，不重写仓库、不迁移生产数据。`frontend/src/pages/Records.jsx` 与 `frontend/src/pages/RepairFinish.jsx` 当前已有未提交修改，后续实施必须继续视为用户改动并避免覆盖或回退。

当前技术形态：根目录为 Node.js/Express + Playwright 瑞云原型，`frontend/` 为 React/Vite，另有少量 Python 演示代码和飞书读取脚本。业务数据主要保存在浏览器 `localStorage`，尚无正式数据库、后端鉴权或持久化服务层。

### 2.2 第一阶段必须重构

1. `frontend/src/shared/crmService.js` 的查询已改为只调用 `/api/crm/repairs/query`，查询后仅展示结果，不创建或推进本地工单。
2. 将连接器拆为明确的 `read` 与 `command` 边界。V1 运行产物只装配 `lookupRepairOrderByLogisticsNo`；`confirmSign` 不应从查询服务可达。
3. 只读入口已命名为 `enterRmaQuery/queryRmaByLogisticsNo`，只允许精确定位扫码输入框、填写物流单号和按回车。
4. 已实现按字段标签解析与 `RECLOUD_SCHEMA_CHANGED`；在采集真实 RMA 详情页脱敏 DOM 后，仍需把通用文本采集替换为经验证的稳定值元素定位器。
5. 统一 V1 请求/响应 DTO、字段命名、状态映射、错误码、请求 ID、超时、脱敏日志与 mock fixture。
6. 前端结果页已展示寄修单号、用户资料、报修描述、取件物流单号和只读标识；录入 SN 按钮禁用并标注待签收模块完成。
7. CORS 不能默认 `*` 用于正式部署；增加服务端鉴权、RBAC、输入校验和限流。
8. 增加写操作总开关，例如 `RECLOUD_WRITE_ENABLED=false`，且与 `DRY_RUN`、权限、人工确认分别校验。当前阶段建议不挂载写路由。

## 3. 分阶段实施

### 阶段 0：安全护栏与契约确认

目标：在任何联调前证明默认不可写。

- 建立 `RECLOUD_WRITE_ENABLED=false`、`DRY_RUN=true` 的双重安全默认；所有写命令再叠加权限、人工确认和幂等键。
- 将 read adapter 与 command adapter 分离，V1 依赖注入中只注册 read adapter。
- 建立 mock 瑞云页面/fixture，不使用真实账号和会话开发自动化测试。
- 根据业务方提供材料冻结 V1 字段表、状态映射和页面选择器。
- 检查 `.gitignore`、提交内容和构建产物，阻止登录状态、账号、环境变量、`node_modules` 与敏感页面快照入库。

退出条件：测试能证明所有写路由未挂载或返回 `WRITE_DISABLED`，查询测试的连接器调用序列不含任何写动作。

### 阶段 1：只读查询闭环（当前首个开发阶段）

流程严格限定为：

```text
扫描物流单号
  → FieldDesk 校验输入
  → 瑞云“服务管理 → 扫码签收”只读查询
  → 回车后直接进入 RMA 详情
  → 读取寄修单号、用户姓名、脱敏手机号、所在地区/地址、报修描述、取件物流单号
  → FieldDesk 展示结果和只读标识
```

实施项：

1. 使用 `POST /api/crm/repairs/query` 作为 V1 只读入口；查询路由只依赖 `queryRmaByLogisticsNo`。
2. 定义 DTO 和结构化错误；手机号/地址按角色脱敏。
3. 通过稳定标签/选择器读取 RMA 详情，不读取变更记录、沟通记录、督办单和产品信息表格中的签收动作。
4. 前端查询入口改用只读 API，结果页处理 loading、成功、未找到、登录失效、超时和结构变化。
5. 记录脱敏查询审计和指标；不创建已签收、检测中或维修中业务状态。
6. 为成功、未找到、字段缺失、登录失效、超时以及“绝不调用签收”编写测试。

退出条件：满足 `PRODUCT_SPEC.md` 的 V1 验收标准；全程使用 mock 完成开发验证。本次文档任务不执行真实瑞云查询。

### 阶段 2：正式数据底座与到店签收

- 按 `DATA_MODEL.md` 评审并建立数据库迁移、仓储层、后端鉴权、RBAC、审计和状态事件。
- 将查询快照与本地工单持久化，建立物流单—寄修单—SN 关系。
- 实现拆包扫 SN、产品类型备注规则和异常隔离。
- 在获得业务明确授权和测试环境后实现“准备签收”与“确认签收”两步命令、幂等和对账；生产仍默认关闭。

### 阶段 3：检测与服务单

- 标准检测表、附件证据、暂停/恢复和完成校验。
- 点击维修后创建瑞云服务单，保存外部单号；对超时先查询后重试。
- 建立检测、服务单和聚合状态的可追溯流转。

### 阶段 4：配件与库存闭环

- 配件主数据、总库/个人库存账户、余额和不可变流水。
- 申请、审批/发料、按 SN 即时使用、释放、退料、旧件归还、报废及库房确认。
- 并发控制、负库存保护、双边调拨守恒、盘点冲销与完整审计。

### 阶段 5：维修完工

- 同步瑞云固定三级故障和话术模板并版本化。

- 完工预检、人工确认、瑞云幂等完工与失败对账。

### 阶段 6：返程发货与运营

- 看板、SLA、告警、同步死信处理、备份恢复与审计报表。

## 4. 第一阶段建议目录与接口边界

```text
server/
  routes/recloud-read.js        # 只读 HTTP 路由
  services/repair-lookup.js     # DTO、映射、权限、脱敏
  integrations/recloud/
    read-adapter.js             # 仅 lookup
    selectors.js                # 经确认的字段定位
    errors.js
  mocks/recloud/                 # 脱敏 fixture
  middleware/request-id.js
  middleware/auth.js
```

现有结构可渐进迁移，不要求一次重写。关键约束是查询 service 的依赖接口不暴露写方法，从类型/模块边界减少误调用风险。

接口以 `PRODUCT_SPEC.md` 中的 `/api/crm/repairs/query` 为准；前端不得使用 `/api/crm/repairs/receive` 完成“查询”。后续若引入统一版本化 API，应提供兼容迁移，不改变 V1 的只读语义。

## 5. 测试与发布门禁

- 单元测试：输入规范化、字段映射、状态映射、脱敏、错误转换和写开关。
- 连接器契约测试：只读 fixture 页面；断言未点击签收、未打开对话框、未填写表单。
- API 测试：认证、权限、限流、请求 ID、各错误码和响应 schema。
- 前端测试：扫码/输入、加载、结果展示和各异常态；不因查询自动推进工单。
- 数据测试（后续）：唯一约束、状态守卫、库存并发、流水守恒、幂等与冲销。
- CI 门禁：根目录测试、前端 lint/build、敏感信息扫描、依赖审计和仅允许预期文件变更。
- 瑞云页面结构变化时先让查询失败并告警，不得使用模糊点击继续执行。

发布采用环境级功能开关。第一阶段生产/测试环境均保持 `RECLOUD_WRITE_ENABLED=false` 与 `DRY_RUN=true`；真实查询也需在业务方提供只读测试环境并明确批准后单独进行。

### 安全 DOM 诊断

真实 RMA 详情定位器未冻结前，可临时设置 `RECLOUD_DOM_DIAGNOSTICS=true`。该模式默认关闭，只在扫码回车并进入详情页后向后端标准错误输出一条 `RECLOUD_FIELD_TITLES` 字段标题数组，不写文件。

诊断日志只输出从 `.rtxpc-form-item` 的 `fieldTitle`、`field-title` 或 label 提取并去重、脱敏后的字段标题数组，格式为 `RECLOUD_FIELD_TITLES: ["字段1", "字段2"]`。禁止输出字段值、input value、客户姓名、手机号、地址、物流号、寄修单号、Cookie、token、完整 HTML、链接或链接参数。

启用诊断时仍必须保持：

```dotenv
DRY_RUN=true
RECLOUD_WRITE_ENABLED=false
RECLOUD_DOM_DIAGNOSTICS=true
```

诊断日志仅用于确认稳定定位器，不得提交到 Git。采集完成后恢复 `RECLOUD_DOM_DIAGNOSTICS=false`。

### 完整电话只读显示

`RECLOUD_REVEAL_PHONE_ENABLED=false` 为默认值。仅显式设置为 `true` 时，查询连接器才会在标题严格为“反馈电话”的 `.rtxpc-form-item` 内寻找“显示数据”按钮；按钮定位、悬停和点击不得越出该表单项。显示失败、无权限、按钮不存在或等待超时时继续返回原脱敏号码，不影响工单查询。

完整电话只用于当次 API 响应和前端内存展示，不得进入服务端日志、字段标题诊断、错误信息、测试快照或 `localStorage`。该操作是只读显示能力，不受 `RECLOUD_WRITE_ENABLED=false` 阻断；签收及其他写操作仍保持禁用。

## 6. 风险与决策点

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 页面自动化选择器不稳定 | 查询突然失败或误操作 | 优先正式 API；稳定字段定位、契约测试、结构变化即停止 |
| Enter 查询本身有副作用 | 违反只读阶段 | 先用脱敏录屏/测试环境确认；不确认则不接真实页 |
| 状态词义不一致 | 错误推进工单 | 保存原始值、版本化映射、未知值阻断 |
| `localStorage` 数据被当正式账 | 丢失、篡改、库存不一致 | 明确仅演示，阶段 2/4 迁移后才开放正式动作 |
| 外部写超时重复执行 | 重复签收/完工/发货 | 幂等键、结果未知状态、先对账后重试 |
| 敏感凭据或客户信息入库 Git/日志 | 安全与合规风险 | 秘密管理、ignore、提交前扫描、日志脱敏 |
