# FieldDesk 产品规格（V1）

## 1. 项目定位

FieldDesk 是面向维修门店的维修执行与瑞云 CRM 自动化系统。它承接 400 客服在瑞云创建寄修单、物流单之后的到店作业，把扫码查询、签收、检测、配件领用、维修完工和返程发货串成可追踪的工单闭环，减少内勤重复录入，同时保留人工确认、权限控制和完整审计。

FieldDesk 是维修执行层，不替代瑞云的客户服务主数据和正式业务单据。瑞云仍是寄修单、服务单以及对外履约状态的权威来源；FieldDesk 保存执行快照、门店作业数据、库存账和同步记录。字段冲突时不得静默覆盖，应标记冲突并由有权限人员处理。

## 2. 产品原则与安全边界

- 先读后写：第一开发阶段只建立查询闭环，不进行任何瑞云写操作。
- 安全默认：所有瑞云写能力必须同时满足功能开关、环境开关、权限、状态前置条件和人工确认；缺少任一条件即拒绝。
- 当前默认：`DRY_RUN=true`，禁止真实签收、库存修改、检测提交、维修完工和返程发货。未配置环境变量也必须等价于禁止写入。
- 查询与命令分离：只读查询接口不得复用会打开弹窗、填写表单或触发状态变化的命令流程。
- 可追溯：状态变化、库存变化、瑞云同步和人工修正都写入不可变操作日志。
- 幂等：以业务单号和操作幂等键避免重复签收、重复扣件、重复完工及重复发货。
- 最小权限：师傅只处理本人任务和个人库存；库房处理库存与归还；管理员管理配置和异常，不默认代替师傅确认业务责任。
- 敏感信息最小化：用户手机号、地址、附件访问地址按角色脱敏和授权；瑞云登录状态、账号、令牌及环境变量不得入库到 Git。

## 3. 用户角色与权限

| 角色 | 核心职责 | 可读范围 | 可执行动作 |
| --- | --- | --- | --- |
| 400 客服（瑞云侧） | 创建寄修单与物流单，维护用户报修信息 | 瑞云内相关客户与单据 | 不通过 FieldDesk 操作；属于流程上游 |
| 维修师傅 | 到店扫码、拆包录入 SN、检测、领用配件、维修、上传附件、选择质保责任 | 分配给本人或本人扫码接收的工单、本人库存 | V1 仅查询；后续可发起签收、检测、配件申请/使用、完工 |
| 库房管理员 | 管理总库、师傅个人库、调拨和归还确认 | 全部库存、库存流水、相关工单摘要 | 后续可发料、调拨、确认归还、盘点与差异处理 |
| 业务管理员 | 用户角色、字典、工单异常、同步任务和审计 | 全部业务数据和日志 | 配置、分配、重试同步、处理异常；高风险写操作仍需明确授权 |
| 系统服务账号 | 执行瑞云/飞书读取和受控同步 | 仅集成所需最小范围 | 当前只读；未来按动作拆分权限与开关 |

建议采用 RBAC 加数据范围控制。权限至少拆分为 `work_order.read`、`receipt.prepare`、`receipt.confirm`、`inspection.submit`、`part.request`、`part.consume`、`inventory.transfer`、`return.confirm`、`repair.complete`、`shipment.create`、`sync.retry`、`audit.read`，不能只靠前端菜单隐藏。

## 4. 端到端维修流程

1. 400 客服在瑞云创建寄修单和物流单，瑞云成为初始单据来源。
2. 机器到店，师傅在 FieldDesk 扫描或输入物流单号。
3. FieldDesk 进入瑞云“服务管理 → 扫码签收”执行只读查询，回车进入 RMA 详情后只读取寄修单号、用户姓名、脱敏手机号、所在地区/地址、用户报修描述和取件物流单号，并将查询结果展示给师傅。
4. 师傅核对机器并拆包扫描 SN；备注按产品类型填写：扫地机填“扫地机”，洗地机填“洗地机”。SN、产品与寄修单必须通过校验。
5. 后续写入阶段由师傅明确确认后，FieldDesk 才同步瑞云签收。V1 不执行此步骤。
6. 工单进入检测节点，师傅记录检测结果和证据。点击“维修”后，瑞云生成服务单；服务单号回写 FieldDesk。V1 不执行此步骤。
7. 师傅按 SN 申请配件，并在实际安装时立即确认使用。系统分别维护总库、师傅个人库、库存流水与工单用件记录。
8. 未使用或拆换后需归还的配件发起归还，只有库房实物核验确认后才调整相应库存并完成归还。
9. 维修完成前，师傅从瑞云固定故障字典中选择三级故障。系统以“固定话术 + 实际更换配件”生成维修措施，师傅可核对但不能伪造实际用件。
10. 师傅选择质保责任，上传要求的照片和视频；完整性校验通过后提交。
11. 后续写入阶段由 FieldDesk 幂等完成瑞云维修节点，记录响应与对账状态。V1 不执行此步骤。
12. 最后由有权限人员在 FieldDesk 发起瑞云返程发货，补充承运商及物流单号并完成对账。V1 不执行此步骤。

异常路径包括：查无物流单、瑞云登录失效、字段缺失、状态不允许签收、SN 重复绑定、服务单生成失败、个人库存不足、重复领用、附件上传失败、同步超时和瑞云/FieldDesk 状态冲突。异常不得被自动跳过或强制推进。

## 5. V1 范围：只读查询闭环

### 5.1 用户故事

维修师傅扫描物流单号后，能够在 FieldDesk 看到瑞云对应寄修信息，确认机器与客户报修信息是否匹配；整个过程不改变瑞云任何字段或状态。

### 5.2 范围内

- 扫描或手工输入物流单号，并做去空格、长度、字符集校验。
- 通过后端只读适配器定位“服务管理 → 扫码签收”查询页面。
- 输入物流单号并按回车，等待瑞云直接进入 RMA 寄修单详情（不存在查询结果列表）。
- 查询并标准化返回：寄修单号、用户姓名、联系电话、所在地区/地址、用户报修描述、产品线、取件物流单号。其中寄修单号、用户报修描述和取件物流单号必需；姓名、电话、地址和产品线允许为空并显示“未提供”。默认返回脱敏电话；只有显式开启只读显示开关且瑞云成功展示时才返回完整电话。
- FieldDesk 展示查询结果、数据来源、查询时间和明确的“只读”标识。
- 处理未找到、登录失效、超时、字段解析失败和瑞云不可用。
- 使用 mock/fixture 完成开发和自动化测试；本次规划不访问真实瑞云。
- 查询操作写审计事件；是否保存业务快照由数据保留规则决定。

### 5.3 范围外

- 扫描或保存 SN、填写备注、确认签收。
- 提交检测、创建或推进瑞云服务单。
- 配件申请、领用、扣减、归还与库存修改。
- 三级故障选择、维修措施生成、质保责任、附件正式上传。
- 瑞云维修完工、返程发货和任何飞书写入。
- RMA 详情页的变更记录、沟通记录和督办单。

这些能力可以保留为现有 UI 演示或后续设计，但必须与生产集成隔离，不得从 V1 查询流程触发。

### 5.4 验收标准

- 输入合法物流单号时，仅调用只读查询接口，页面展示全部约定的 RMA 工单字段。
- 浏览器自动化不得点击“签收”，不得打开签收确认弹窗，不得填写任何瑞云表单。
- 后端与连接器的调用测试能证明只执行 `query`，无 `confirmSign` 或其他命令调用。
- `DRY_RUN` 缺失或为任意非显式授权值时，所有写操作均返回拒绝；第一阶段建议写路由直接不挂载或返回 `403 WRITE_DISABLED`。
- 同一查询可重复执行，不产生瑞云或 FieldDesk 业务状态变化。
- 日志不记录完整手机号、地址、Cookie、令牌或页面 HTML。
- mock 成功、未找到、登录失效、超时和字段缺失场景均有测试。

## 6. V1 只读接口设计

### `POST /api/crm/repairs/query`

请求：

```json
{
  "logisticsNo": "TEST-SCAN-0001"
}
```

成功响应：

```json
{
  "success": true,
  "data": {
    "logisticsNo": "TEST-SCAN-0001",
    "rmaNo": "RMA-TEST-0001",
    "customer": {
      "name": "测试用户甲",
      "phoneMasked": "139****0000",
      "regionAddress": "测试省测试市测试区"
    },
    "reportedFault": "测试机器启动后停止运行",
    "productLine": "测试产品线",
    "pickupLogisticsNo": "TEST-PICKUP-0001",
    "readOnly": true
  }
}
```

错误格式：

```json
{
  "success": false,
  "code": "RECLOUD_ORDER_NOT_FOUND",
  "message": "没有查询到对应的瑞云 RMA 寄修单"
}
```

建议错误码：`INVALID_LOGISTICS_NO`（400）、`RECLOUD_ORDER_NOT_FOUND`（404）、`RECLOUD_LOGIN_REQUIRED`（502）、`RECLOUD_QUERY_TIMEOUT`（504）、`RECLOUD_SCHEMA_CHANGED`（502）、`RECLOUD_UNAVAILABLE`（503）和 `WRITE_DISABLED`（403）。对前端只返回可操作提示，详细错误写脱敏日志。

连接器契约为 `queryRmaByLogisticsNo(page, logisticsNo)`。它只能定位扫码输入框、填写查询条件、按回车并读取详情；代码审查时禁止依赖 `confirmSign`，并通过 mock 调用序列测试约束。`/api/crm/repairs/receive` 不属于 V1，前端不暴露调用，服务端默认以 `RECLOUD_WRITE_ENABLED=false` 在打开瑞云前拒绝。

## 7. 非功能要求

- 查询目标响应时间：正常情况下 P95 小于 8 秒；超时可配置但必须有限。
- 可用性：瑞云不可用时明确提示并允许安全重试，不返回伪造数据。
- 安全：服务端鉴权、RBAC、限流、输入校验、CSRF/同源策略、秘密管理和敏感字段脱敏。
- 审计：记录请求人、门店、物流单号摘要、结果、耗时、错误码和关联 ID。
- 可观测性：区分登录失效、页面结构变化、无结果与网络故障。
- 兼容性：保存瑞云原始状态值及映射版本，避免字典变化导致历史语义丢失。

## 8. 下一阶段需要业务方提供

### 瑞云页面与字段

- “服务管理 → 扫码签收”的菜单路径、页面 URL、测试环境/测试账号及其只读权限说明。
- 已确认扫码输入框的完整 placeholder 为“请用扫码枪输入物流单号/工单号/订单号/退换单”；仍需 RMA 详情页字段容器的脱敏 DOM。
- 需要采集寄修单号、用户姓名、脱敏手机号、所在地区/地址、用户报修描述、取件物流单号各自的标签元素、值元素及共同父容器（保留标签名、稳定 class、`data-*` 属性和相对层级）。
- 需要采集详情页可判定加载完成的稳定元素或 URL 特征，以及未找到工单的提示元素和精确文案。
- 需要确认上述六项字段是否始终存在、地址是否拆成地区与详细地址两个 DOM 字段、报修描述是否为富文本。
- 不需要采集产品信息表格中的“签收”按钮；V1 自动化明确禁止定位或点击该按钮。
- 后续签收弹窗中 SN、备注、产品类型和确认按钮字段，以及签收成功的可靠判据。
- 检测节点、点击维修后服务单生成、固定三级故障、质保责任、附件、完工和返程发货页面的字段与状态变化。
- 是否有正式 API、Webhook 或导出能力；如有，应优先于页面自动化，并提供接口文档、限流及幂等规则。

### 飞书表格字段

- 表格用途、所有者、文档/表格标识的安全配置方式，不在代码中硬编码 token。
- 工作表名称及列头：产品线、品牌、产品名称、型号、项目编码、SN 规则、三级故障编码/名称、固定话术、物料编码/名称等实际字段。
- 主键、唯一性、必填项、数据类型、枚举、空值含义、有效期、版本和停用标识。
- 表头所在行、数据起始行、公式/合并单元格、最大数据量和刷新频率。
- 读取范围、是否允许写入、谁负责审核数据以及历史版本保留要求。

### 业务规则

- 物流单、寄修单、SN、服务单之间的基数与唯一性规则。
- SN 格式、扫码失败处理、SN 与型号不匹配及同一 SN 重复维修的处理。
- 扫地机/洗地机的判定来源及备注固定值，其他产品类别如何处理。
- 各节点进入/退出条件、撤回/返工/取消规则及超时升级规则。
- 服务单生成时机与失败补偿；三级故障字典层级和必选数量。
- 配件申请、即时使用、撤销、退料、旧件归还、报废、串码件和负库存规则。
- 总库与个人库的账权威来源、库房确认边界、盘点差异与跨师傅调拨规则。
- “固定话术 + 实际更换配件”的准确模板、排序、同名配件合并和无换件文案。
- 质保责任枚举、判定主体、必传照片/视频清单、格式、大小和留存期限。
- 返程承运商、运单生成/录入、收件信息校验和发货撤销规则。
- 数据保留、手机号/地址脱敏、审计期限、门店隔离和异常人工处理责任人。
