# 本地正式做单告警

启动：`node scripts/start-business-alerts.js`。必须显式设置 `FEISHU_BUSINESS_ALERTS_ENABLED=true`、`FEISHU_ALERT_OPEN_ID` 和已有飞书应用凭据。凭据及收件人只放本地私密配置，禁止提交 Git。当前仅支持 JSON 数据部署，SQLite 会拒绝启动。

这是独立只读进程，不重启 API，不操作瑞云，也不补提工单。每次扫描完成后等待 10 秒再扫描：读取签收、项目核对、签收附件、检测、建维修单、维修资料，以及 outbox 完工/寄回/完结任务。失败和结果未知产生告警；活动状态超过对应 90/120/180 秒门槛产生卡住告警。阈值只表示需要检查，不断言远端失败。消息仅包含工单号、步骤、固定说明及故障编号，不含客户电话、附件或原始异常文本。

首次启动将当时已有异常作为历史基线抑制；历史异常明确成功后再发生新故障才通知。同一故障周期一次 OPEN 和一次 RECOVERED；只有 CONFIRMED/SUCCESS 才确认恢复，记录消失、取消或读取失败不产生恢复消息。恢复说明仅代表本地状态记录成功，不能代替人工核验真实瑞云内容。重启复用持久化故障与投递记录。

状态保存在数据目录 `business-alerts`，包含独占 `monitor.lock`、`incidents.json` 和 `deliveries`。进程正常停止会释放锁；强杀后残留锁需先核实原进程已退出再人工处理，不能盲目删除锁。保持单实例，不支持分布式运行。历史基线和故障记录不自动删除。

投递 SENT 仅表示飞书接口接受。429 最多重试三次；失败/结果未知保留记录，不盲目重复发送，当前仍需人工检查投递异常。本功能不是全系统监控：不覆盖页面校验错误、所有 HTTP 错误、未写入记录的故障、API 进程退出或电脑断电。独立监测进程自身退出不会自行恢复，也未安装开机启动/外部心跳监测。不能把没有飞书消息理解为系统无故障。

测试：`node --test test/business-alert-monitor.test.js test/feishu-alert-notifier.test.js` 使用模拟发送器，无外部消息。隔离恢复套件也包含业务告警测试。
