## 必须处理的部署阻碍

1. 附件路径：server.js 默认维修、签收附件位于程序目录 database/uploads。systemd 使用 ProtectSystem=strict，只允许 /var/lib/fielddesk 等目录写入；按模板直接部署可能无法上传。需统一所有附件类别实际路径、权限及备份范围并测试。
2. 备份路径：生产数据目录为 /var/lib/fielddesk，新备份默认同级 uploads 会推导为 /var/lib/uploads，并非当前附件目录。必须显式配置并与运行时路径一致。
3. Nginx 请求大小：client_max_body_size 30m，但后端允许140mb请求、100000000字节文件；base64还会膨胀。须统一允许大小和提示，验证代理层真实上传。
4. Nginx 按公网IP对整个 /api/ 限制10r/s、burst30，多位同网师傅共用额度。此前账号级限流测试未包含此代理，需重新设计并测试混合并发。
5. 正式守护/告警未接入：systemd仅有Restart配置，发送组件没有正式启动入口；隔离演练不替代服务器安装、开机启动及恢复失败通知验收。
6. 备份仍要求停写，SQLite在线一致性、定时/异地备份及恢复流程未完成。
7. 瑞云真实多单并发、大视频持续负载、任务结果未知后的人工处理流程仍须验收。当前未知投递记录不会盲目重发，但也未实现补偿界面。

建议先修1—4并完成针对测试，再准备目标服务器参数与正式守护接入。不要为了允许上传而直接关闭systemd只读保护；不要单纯无限提高所有限流和文件大小。
